The problem

An employee record and a directory account represent the same person in different systems. Creating and disabling accounts manually makes it easy for those records to drift apart.

This project brings employee management and directory synchronization into one interface. The focus is the account lifecycle and visibility into administrative actions.

Architecture

The Flask application provides the management interface and authentication. MySQL stores HR data. A separate Python synchronization module communicates with Active Directory using ldap3.

HR databaseMySQL
Identity serviceFlask + ldap3
Active DirectoryAccounts + groups

Simplified architecture illustration; not a live system dashboard.

Implementation notes

  • A Flask interface manages employee records and initiates synchronization.
  • The synchronization module reads HR records from MySQL and creates or disables directory accounts through LDAP.
  • TOTP-based two-factor verification adds a separate step to the administrator login flow.
  • Audit logging records administrative actions and supports reviewing what happened.

Where to look in the code

app.py contains the Flask routes, authentication and audit handling.

sync_hr_ad.py contains the MySQL-to-Active Directory synchronization logic.

Limitations & next steps

Design consideration: HR records and directory accounts can drift apart. Synchronization needs visible outcomes and a clear recovery path when a directory operation fails.

The next iteration focuses on repeatable synchronization, recovery, and a reproducible demonstration setup.

Next steps

  • Document the expected results of each account lifecycle scenario, including repeated synchronization.
  • Test directory outages and partial failures, and document how to recover safely.
  • Add reproducible setup instructions and a walkthrough using a demonstration directory.
